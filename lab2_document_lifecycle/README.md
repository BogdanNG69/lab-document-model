# Лабораторна робота №2 — Життєвий цикл електронного документа та версійність

**Дисципліна:** Системи електронного документообігу
**Варіант:** 8 — Заява працівника на відпустку

## Опис

Розширення моделі документа з лабораторної роботи №1: додано життєвий
цикл (статуси та дозволені переходи між ними), історію змін статусів
та механізм версійності, який враховує редагування змістовних полів.

## Схема життєвого циклу
draft → submitted → manager_review → approved → hr → completed
↓
rejected → draft

## Таблиця переходів

| Поточний статус | Дозволений наступний статус |
|---|---|
| draft | submitted |
| submitted | manager_review |
| manager_review | approved, rejected |
| rejected | draft |
| approved | hr |
| hr | completed |
| completed | — (кінцевий стан) |

## Структура
lab2_document_lifecycle/
├── document.json — документ з полем history
├── lifecycle_main.py — логіка переходів, редагування, версійності
└── README.md

## Запуск
py lifecycle_main.py

## Функціонал

- перевірка дозволених переходів між статусами;
- блокування заборонених переходів (статус не змінюється);
- ведення історії переходів з автоматичною датою/часом;
- редагування полів документа (дати відпустки);
- автоматичне збільшення версії при зміні змістовних полів;
- версія НЕ змінюється при простій зміні статусу;
- збереження оновленого документа назад у JSON.

## Результати перевірок

1. Коректний перехід (draft → submitted) — виконано, запис додано в history.
2. Заборонений перехід (submitted → hr) — відхилено, статус не змінився.
3. Редагування дат відпустки — версія збільшилась з 1 до 2.
4. Перехід без редагування (submitted → manager_review) — версія залишилась незмінною.
5. Повна історія переходів виведена у хронологічному порядку.
6. Спроба виходу з кінцевого стану completed — відхилено.
